## 2. 版本模型

- 平台版本: 根目录 `VERSION`。
- 文档版本: 每篇文档头部 `当前版本`，必须与平台版本一致。
- 普通文档兼容范围: `兼容平台版本`（列表）。
- `req-01/req-02/roadmap-01`: 使用单值 `对应平台版本`。
- `req-00/roadmap-00`: 使用单值 `目标版本`。

## 3. 版本号格式

- 平台版本使用 `MAJOR.MINOR.PATCH`。
- 文档不维护独立语义化版本号，直接对齐平台版本。

语义约定：
- `PATCH`: 文案澄清、错字修复、非语义变更。
- `MINOR`: 新增能力、需求条目、流程规则。
- `MAJOR`: 不兼容变更或模型重构。

## 4. 文档头部规约（MUST）

- `req-00-draft.md`: `目标版本`、`作用`。
- `req-01/req-02`: `当前版本`、`对应平台版本`、`作用`。
- `roadmap-00`: `当前版本`、`目标版本`、`作用`（且 `当前版本` 必须等于 `目标版本`）。
- `roadmap-01`: `当前版本`、`对应平台版本`、`作用`。
- 其他文档: `当前版本`、`兼容平台版本`、`作用`。

## 5. 变更门禁（MUST）

- 仅在准备提交（commit）时修改平台版本（`VERSION`）。
- 文档版本号不得独立提升，始终与平台版本保持一致。
- 同一平台版本下的多次文档改动：在同一行 `summary` 中使用 `<br>` 追加，不重复新增版本号行。
- 使用 `<br>` 追加时必须带序号（`1.`、`2.`、`3.`...）。

## 6. 发布核验（MUST）

1. 更新根目录 `VERSION`。
2. 核验 `roadmap-00` 当前目标版本不存在 `PENDING`/`IN_PROGRESS`/`BLOCKED`。
3. 将 `DONE` 任务归档到 `roadmap-01`。
4. 发布后回填 `req-01` 和 `req-02`。
5. 归档完成后清空 `req-00` 与 `roadmap-00` 的已发布版本条目，并切换下一目标版本。
