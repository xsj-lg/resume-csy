## 2. 开工前校验（MUST）

- 先读取 `docs/docs-index.md`。
- 每次执行任务前，必须完整阅读一遍 `docs/00-governance/` 当前生效的治理文档，不得仅凭记忆、历史上下文或单篇摘录执行。
- 涉及需求实现，检查 `req-00` 与 `roadmap-00` 对齐情况。

## 3. 行为要求（MUST）

1. 先澄清目标、范围、影响文件、验收条件。
2. 变更最小化，仅改目标直接相关文件。
3. 不杜撰需求状态、发布事实、术语定义。
4. 输出必须包含关键改动路径与变更目的。
5. 只要涉及新增、修改、删除任何文件，必须先向用户说明拟修改文件路径、修改目的与影响范围。
6. 在用户明确同意前，不得执行文件写入操作；默认只进行只读检查、分析和方案输出。
7. 只要涉及代码文件或其他项目文件变更，必须同步判断是否影响 `project-docs/` 描述；若影响，必须在同次交付中更新对应文档，不得只改实现不改说明。
8. `project-docs` 的同步目标文档优先以 `project-docs/development/development-and-integration-guidelines.md` 第 10 节映射为准；若映射不足以覆盖本次变更，必须显式说明假设、缺口或阻塞，不得杜撰文档事实。

## 4. 交付要求（MUST）

- 每次交付明确：
  - 变更文件
  - 需求编号
  - roadmap 条目状态
  - `project-docs` 是否已同步更新；若未更新，说明原因
  - 风险与未完成项
- 发布准备时附加核验：
  - `roadmap-00` 待处理计数是否为 0
  - `roadmap-01` 是否完成归档
