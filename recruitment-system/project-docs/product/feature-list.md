# 功能清单文档

本文档用于说明 `recruitment-system` 当前已经落地的产品能力、角色边界、核心流程和已知限制。

## 1. 产品定位

系统当前是一套面向内部招聘流程的简历筛选工作台，覆盖登录、用户管理、岗位管理、简历导入、候选人面试流程管理、简历结构化抽取、AI 自动评分，以及管理员可见的操作记录审计能力。

## 2. 角色与权限

| 角色 | 角色码 | 当前能力边界 |
| --- | --- | --- |
| 管理员 | `administrator` | 查看所有页面；管理用户；查看 LLM 只读配置；查看全部岗位与候选人；查看操作记录页 |
| HR / 招聘专员 | `hr_specialist` | 查看工作台与岗位管理；上传简历；同步本地简历目录；编辑候选人通用信息；推进流程；维护岗位与评分表 |
| 面试官 | `interviewer` | 查看被分配候选人；填写已分配轮次的面评；不能上传简历、不能管理岗位、不能管理用户 |
| 部门负责人 / 用人经理 | `hiring_manager` | 仅查看本部门岗位和候选人；可填写 `二面` / `HR面` 面评并在关键轮次推进流程；不能管理用户；不能上传简历；不能维护岗位评分表 |

补充说明：

- 部门范围目前固定为 `销售部`、`研发部`、`算法部`、`项目部`、`人事部`。
- 部门负责人必须设置 `department_scope`。
- 首次登录或被管理员重置密码后，用户必须修改密码才能继续访问业务接口。
- 操作记录页与 `/api/operation-logs*` 仅管理员可见。

## 3. 已实现模块

### 3.1 认证与会话

- 用户名密码登录。
- 登录成功后由服务端写入 `RS_SESSION` HttpOnly Cookie。
- 支持获取当前登录用户信息。
- 支持退出登录。
- 支持修改本人密码。
- 管理员可重置其他用户密码。

### 3.2 用户与角色管理

- 管理员可创建用户。
- 管理员可编辑显示名、启用状态、角色、部门范围。
- 用户列表可查看 `must_change_password` 状态。
- 用户管理页内置大模型配置只读面板，调用 `/api/settings/llm-config` 展示当前运行配置摘要。

### 3.3 岗位管理

- 岗位基础信息：岗位名称、岗位编码、部门、招聘人数、地点、招聘负责人、用人经理。
- 文本配置：岗位 JD、任职要求。
- 固定流程配置：初筛、一面、二面、HR 面评价要求。
- 筛选标准配置：学历、专业、技能、项目经验。
- 状态管理：`open` / `closed`。
- 支持岗位复制与关闭。
- 支持岗位内关键操作日志回显。
- 岗位管理页右侧支持进入“简历结果导出”页，但该入口仅管理员与人事经理可见。
- 简历结果导出页支持按简历上传时间筛选，并展示筛选结果统计：总简历数、已面试完数、通过数、未通过数，以及当前处于 `初筛`、`一面`、`二面`、`HR面` 的数量。
- 简历结果导出页支持导出当前筛选结果，导出表格包含上传时间、简历人员、四阶段各自面试人和当前简历状态。

### 3.4 评分表管理

- 支持为岗位上传 `csv` / `xls` / `xlsx` 评分表。
- 单文件大小限制 `8MB`。
- 上传后按规则解析预览，提取维度、评估点、标准、分值。
- 岗位保留评分表版本列表与当前生效版本。
- 删除生效版本时，会自动切换到剩余的最新版本；若已无版本，则关闭自动评分。

### 3.5 简历导入与候选人管理

- 支持从工作台上传 PDF 或图片简历。
- 单文件大小受后端统一上限 `20MB` 限制。
- 上传时必须绑定岗位与部门，并写入候选人档案中的 `job_id/job_code/job_title` 与岗位快照。
- 支持同步扫描 `data/cv/ais/` 下的本地 PDF 文件。
- 支持删除候选人，同时删除档案、轮次记录、自动评分记录和简历文件。

上传完成后系统会在后台异步调度结构化抽取与 AI 自动评分，前端可以通过评估接口轮询结果或手动触发 `/auto-score`、`/resume-extract`。

### 3.6 候选人列表与工作台

- 候选人列表支持按 `stage_status`、`school`、`education`、`duration`、`score`、`upload_date` 等维度筛选。
- 支持候选人排序、星标和详情联动预览。
- 支持面试日历视图。
- 工作台会记住最近查看的候选人；离开页面再返回时，若候选人仍可见，会自动恢复上次查看上下文。

### 3.7 面试流程管理

- 当前固定面试阶段：`初筛`、`一面`、`二面`、`HR面`。
- 支持阶段动作：`next`、`end`、`reset`。
- 阶段状态保存在 `candidate_profiles.stage_status_json`。
- 支持按阶段保存面试时间、面试人、拟提问、面评内容。

### 3.8 简历结构化抽取

- 支持从简历 PDF 文本中抽取并回写结构化信息。
- 上传图片简历时，会沿用本地 PDF 解析服务的同一上传接口获取文本内容，再进入既有抽取链路。
- 上传后立即执行简要抽取，例如手机号、邮箱和简历预览片段。
- 上传后的规则初抽结果会先用于页面结构化区域即时回显。
- 深度结构化与自动评分随后在后台任务中完成，并按字段级用大模型有效结果替换已有展示值。
- PDF 解析服务的 URL、超时和失败回退开关已外置到独立配置文件，便于本地与部署环境调整。
- 首次 PDF 解析结果会缓存到数据库，后续再次获取简历文本时优先复用缓存，减少重复解析调用。
- 当 PDF 解析服务不可达、超时、返回异常或空结果时，系统会自动回退旧的 PDF 文本提取工具，并继续把结果写入数据库缓存。
- 当上传文件为图片且本地解析服务不可达、超时、返回异常、非法 JSON 或空结果时，接口直接返回解析失败，不走 PDF 旧工具回退链路。
- 手动重新触发简历结构化抽取时，如缓存已存在，也会优先复用已落库的简历解析结果。
- 自动评分过程中即使 LLM 调用异常，已成功写入的 PDF 解析缓存也会保留，不随评分事务回滚。
- 当大模型未抽出字段、字段为空或无效时，页面会保留规则初抽或人工已有值，不会被空结果覆盖。
- 结构化抽取中的有效姓名会同步更新候选人主名称字段，列表和详情页通用信息保持同一姓名来源。
- 当前界面展示的抽取结果包括：姓名、电话、邮箱、城市、专业、技能、证书、个人摘要、教育经历、工作经历、项目经历。
- 抽取状态、来源、模型、错误信息和更新时间会写入候选人档案表。

### 3.9 AI 自动评分

- 候选人关联岗位且岗位启用自动评分时，上传简历后会在后台异步调度评分。
- 支持手动重新触发自动评分。
- 自动评分读取简历文本时优先复用数据库中的 PDF 解析缓存。
- 评分输入优先使用岗位快照中的结构化评分表与候选人结构化简历信息。
- 评分结果包含总分、维度分、风险提示、总结、匹配等级等信息。
- 当 LLM 不可用时，服务端会降级使用规则评分。
- 自动评分记录独立落表，保留模型名、Prompt ID、原始结果和时间戳。

### 3.10 操作记录审计

- 管理员可访问操作记录页 `/static/operations.html`。
- 支持按关键词、模块、操作类型、操作人、业务对象、结果、来源和时间范围筛选。
- 支持查看单条日志详情。
- 支持对同一业务对象的上一条记录做差异比对。
- 支持导出当前筛选结果 JSON / CSV，以及单条详情 JSON。
- 关键操作留痕已落独立表 `operation_logs`。

## 4. 主要业务流程

1. 管理员创建用户并分配角色。
2. HR 登录后创建岗位，维护 JD、流程要求、筛选标准和评分表。
3. HR 上传 PDF 或图片简历，并在上传时绑定岗位与部门。
4. 系统创建候选人档案、生成岗位快照，并在条件满足时触发自动评分。
5. HR、面试官、部门负责人按权限查看候选人，其中 HR 负责档案维护与初筛，面试官负责已分配轮次面评，部门负责人负责 `二面` / `HR面` 的关键轮次决策。
6. 管理员可在操作记录页查询和导出关键操作留痕。

## 5. 当前已知限制

- 后端不是 FastAPI/Flask，而是基于 `http.server` 的单进程 HTTP 服务。
- 认证目前是服务端 Cookie Session，不是 JWT。
- 数据库为本地 SQLite，适合单机部署，不适合高并发多实例共享写入。
- 操作记录页当前入口是 `/static/operations.html`，没有单独的 `/operations` 页面路由。
- 前端仍保留少量 `localStorage` 状态缓存以改善交互。
- 项目目前未看到完整自动化测试套件，现有验证主要依赖 `py_compile`、`node --check` 和手工联调。

## 6. 2026-03-27 权限补充

- 角色模型以五类角色为准：`administrator`、`hr_specialist`、`personnel_manager`、`engineering_manager`、`algorithm_manager`。
- `administrator`、`hr_specialist`、`personnel_manager` 可查看全部候选人列表、详情和简历预览。
- `administrator`、`personnel_manager` 可访问简历结果导出页并执行结果导出；`hr_specialist` 虽可访问岗位管理页，但不可见结果导出入口，也不可访问该页面和导出接口。
- `engineering_manager`、`algorithm_manager` 仅可查看在 `一面` 或 `二面` 任一阶段中被指派给自己的候选人。
- 若在 `初筛` 阶段明确指定了负责人，该候选人会立即进入该负责人的可见范围，确保第一阶段分配后即可查看简历与详情。
- `engineering_manager`、`algorithm_manager` 仅可写入自己被指派负责的 `一面` / `二面` 轮次；未指派时访问详情、简历和保存轮次接口应返回禁止。
- `初筛` 阶段的负责人下拉支持正常指定活跃用户；`一面` / `二面` 负责人下拉仅展示 `engineering_manager` 与 `algorithm_manager`。
- 工作台中的 `一面` / `二面` 负责人选择仅展示 `engineering_manager` 与 `algorithm_manager`。
- 工作台会在“面试阶段”区域展示当前面试人的角色，便于确认当前负责人身份。
- `重置阶段状态` 会清空该候选人的全部阶段面试人，并把流程恢复到 `初筛`。
- 阶段动作入口已下沉到“阶段面评信息”区域，按钮固定为 `通过并进入下阶段`、`未通过`、`重置阶段`。
- 点击 `通过并进入下阶段` 时，系统会先保存当前阶段面评，再要求补录下一阶段的面试时间与阶段面试人，然后才推进流程。
- 当前阶段被明确指派的面试人可执行 `通过并进入下阶段` 与 `未通过`；其中研发经理、算法经理在自己负责的 `初筛`、`一面`、`二面` 候选人上也可补录下一阶段安排并推进流程，`重置阶段` 仍保留原高权限边界。
- 岗位管理页访问角色为 `administrator`、`hr_specialist`、`personnel_manager`；研发经理和算法经理无岗位管理入口。
- 岗位管理页中的“简历结果导出”入口与导出页访问权限进一步收紧为 `administrator`、`personnel_manager`。
